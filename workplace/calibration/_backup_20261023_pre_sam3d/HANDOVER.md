# 交接：Pose6DAug 式「网格 + 分层合成」换物（更新于 2026-10-15）

工作目录 `workplace/calibration/`。主脚本 `pose6d_swap.py`（腕/up 两视图的分层合成），
底层渲染器 `meshrender.py`。**下次从这里接着做。**

## 一句话现状

用户要的三层（L0 抹原物体+补背景 → L1 渲新物体 → L2 **把原视频的机器人前景贴回去**）
在**腕视图全程 163 帧验过**，红线 0 帧越界。这一轮把两项从「占位/解析近似」推进到
**从数据实测**：方块的常量 6D 位姿（Stage 2）、场景光照（Stage 4）；并修掉一个把球
烧成白斑的材质串用 bug。

**两个视图的 L1 现在都是球网格光栅**（up 视图这一轮刚从 `BS.draw_ball` 的解析圆换过来）。

**2026-10-15 追加（本轮最后一件事，见 §7）**：up 视图的 **L2 定了终稿** ——
用户报的「球盖在夹爪上」不是掩码调参能修的，是**判据选错了**：不该用颜色判据
（手指的暗面、桌面阴影都是低饱和，分不开），而该用「**旧物体在哪儿露出来**」
（＝擦除掩码 `cm`）。改完 up 视图的 L2 由「贴回手指」变成「**除 `cm` 外一律回原帧**」，
夹爪永远在球前面（构造性保证，`outside_px` 恒 0）。

**位姿增强（原 Stage 5）本轮明确不做**（见 §8），「宁可漏增强不要错增强」这条
判据也已作废（见 §7 末）。

## 本轮做了什么

### 1. Stage 2：方块在腕相机系的常量 6D 位姿（新 `held_pose.py` → `calib/held_pose_wrist.json`）

没有深度传感器，位姿只能靠**剪影 + 已知边长**（实测 21.5mm）反解。拟合输出：

| 量 | 值 | 说明 |
|---|---|---|
| `T_cam_cube` 平移 | `[-1.04, -25.38, 106.9]` mm | 相机系里的**常量**（搬运期方块与相机刚性固定） |
| `cube_edge_mm` | **21.19** | 对照实测 21.5 ⇒ **差 1.4%**，是这套拟合的独立自洽证据 |
| 逐帧剪影 IoU | 中位 **0.872**，min 0.243，max 0.917 | 163 帧全跑 |
| IoU < 0.5 的帧 | **35/163**，且**全在 f246~f285** | 见下 |

那 35 帧全部落在夹持最初 40 帧，**独立复现了已知的滑动**（腕图方块形心 f246 (273,138)
→ f292 (314,110) 之后钉死）。这条不是「拟合不好」，是**数据里真有初期的滑动/沉降**，
所以位姿增强必须只在 f292 之后的稳定段做。

产物图：`figures/pose6d_cube_refit.png`（原帧 / 观测轮廓+渲染轮廓 / 网格重渲 / |Δ|）、
`figures/pose6d_iou_vs_frame.png`（IoU 曲线，单序列 + 0.5 阈值线 + 「初期未稳定」带）。

### 2. Stage 4：从实测像素拟合光照（新 `light_fit.py` → `calib/wrist_lighting.json`）

做法：拿 Stage 2 的位姿把方块网格**渲回原帧**，逐像素得到法线；再取同一像素在真实视频里的
颜色 —— 就成了「法线 → 亮度」的观测。方块在相机系是常量位姿，而相机随臂在场景里转，
所以同一块面在 base 系里逐帧法线不同，**光的方向就被这些变化钉住了**（只看桌面定不出来，
桌面只有一个法线）。

外层 4 个非线性参数（az、el、环境占比 a、高光指数）走 Nelder-Mead + 网格多起点；
内层 (albedo BGR, specular) 是线性的，直接最小二乘。60000 px / 37 帧。

| 量 | 值 |
|---|---|
| 平均 \|ΔBGR\| | **9.92**（占位光照同像素集 **52.45**）⇒ 改善 **81%** |
| 光方向（base 系，指向光源） | `[-0.1773, 0.8308, 0.5275]`，az **102.0°** el **31.8°** |
| ambient / diffuse | 0.538 / 0.462 |
| specular / shininess | 1.0（**顶到界**）/ 10.4 |
| 方块 albedo（BGR） | `[0.2756, 0.8019, 0.9637]` |

### 3. 修掉「把方块的镜面率串到球上」的 bug（**这条最该记住**）

`meshrender.shade` 的镜面项是**三通道等量相加**、上限就是 `specular` ——
所以 `specular` 这个数**本身就是「高光能白到什么程度」**。无约束最小二乘把它解到
**11.01**（镜面反射率 >1 不物理），它的作用是**吸收模型误差**，在方块自己身上看不出来
（残差 9.72 还很漂亮）。一亮相在球上就露馅：

| 球的镜面设置 | 被 clip 到 ≥250 的球像素 | **三通道全 ≥200（纯白斑）** |
|---|---|---|
| 11.01 / 19（照抄方块） | 36.6% | **27.8%** ← 图上一眼「红圈 + 一块白」 |
| 1.0 / 10.4（带界重拟合） | 29.6% | 9.0% |
| **0.25 / 48（现在用的）** | 3.3% | **0.0%** |

**根因是分解错了，不是参数范围**：镜面反射率是**物性（属于物体 BRDF）**，不是光的属性。
拟合出来的那个数属于**方块**（黄塑料本来就亮）。红球是另一种材质，镜面率得单独定。

所以代码里分成两件事：`load_lighting()` 给的是**实测的光**（方向 + ambient/diffuse 配比）；
`ball_material()` 把球的材质套上去。球的 `BALL_ALBEDO (0.18,0.24,0.88)` BGR 和
`BALL_SPECULAR 0.25 / BALL_SHININESS 48` **都是设计选择**（新物体的材质本来就由我们定），
但**光是从数据实测的**，这一点在代码注释和 json 的 `material_caveat` 里都写明了。
数字由 `/tmp/_zo.py` 扫出来的。

> 重拟合（内层带界 `albedo, specular ∈ [0,1]`）残差只从 9.72 掉到 9.92 —— 代价 0.2，
> 却把**不物理的参数挡在解空间外**。带界后 specular 顶到 1.0、shininess 反降到 10.4
> （高光更宽），说明**光靠加界救不了球**，必须走上面的材质分离。

### 4. up 视图 L2 独立复核：0% 是旧方块像素

`/tmp/_zk.py` 抽样 28 帧：L2 掩码里 **落在方块掩码内的 = 0%**、**偏黄的 = 0%**
（逐帧都是 0）。L2 的 HSV 中位 (6,18,227) 是**暖光下的浅灰**（手指），不是饱和黄。
⇒ up 的 L2 贴回去的确实是**真手指像素**，不会把旧方块画回新球上（腕视图那个 bug 没在
up 重演）。

顺带查出：**up 视图的跟踪掩码是「楔形」不是方块轮廓**（楔=露出来的那条黄边，
228→2595px 一路变）。所以**任何「拿这个掩码当尺寸尺」的用法都不成立**。

### 5. up 相机的 K 与外参：均已标定（2026-10-19），D = 684.7mm

`/tmp/_zn.py`：假设 up 用前相机那颗镜头（同型号 icSpring，都 640×480），拿
`up_homography.json` 分解，自洽度判据直接否掉 —— 归一化后 `|m1|/|m2| = 1.097`、
`r1·r2 = −2.6e−2`（不是正交单位阵）。扫焦距看正交性，最好处落在 `fx ≈ 1300~1700`，
也就是**单平面标定的经典退化：焦距与高度不可分辨**（见记忆 `up-camera-height-is-unidentifiable`）。

**2026-10-19 更新（部分推翻上面的负面结论）**：`up_intrinsics.py` 用 **32 个**
手持板姿势（首轮 20 + 补拍 12 张左右倾）解出 up 内参：
`fx = fy = 1228.79px, cx,cy = 298.84,242.75, k1 = −0.4463,
p1,p2 = −0.00501,+0.00114`（k2 = k3 = 0），rms **0.404px**；
产物 `calib/up_intrinsics.json`、`figures/up_intrinsics_check.png`。
首轮 20 张的解备份在 `calib/up_intrinsics.json.bak-20views-20261019`。
用这组 K 再分解 `up_homography.json`：`||m1||/||m2|| = 1.021`、
`m1·m2 = −0.006`（K 未知时是 1.097 / −0.026），解出
**D = 707.3mm、光轴倾角 23.4°**，和名义 700mm、下面 §6 的「~20° 斜」一致。
但按新 K+dist 去畸变后重分解得 **D = 665.7mm、28.3°**（旧单应没有内参，
和新 K 有几 % 的不自洽）。所以：

- **f 已标定**（1228.79px），不再是不可辨识的自由度；1182/597 是渲染的等效焦距，
  不是标定值；
- **D 已由平放板 PnP 钉住 = 684.7mm**（2026-10-19）。板平放在
  `board_to_base.json` 解算时的同一物理位姿（板位差 +1.3/−5.4mm、−1.83°），
  用 §2b 的 K+dist 做 `solvePnP(..., SOLVEPNP_IPPE)`，PnP rms **0.160px**；
  `T_base_cam` 平移 **(459.13, 77.52, 684.67)mm**，光轴 (−0.4326, −0.0859, −0.8975)，
  与垂直向下夹角 **26.2°**（up 机位固有的斜视）。产物 `calib/up_camera_pose.json`；
- 684.7mm 落在旧单应分解的 665.7–707.3mm 区间内，倾角也一致，三条路径互相印证；
  尺度仍按名义 25mm 板格，实测 100mm 边长差 1% → D 差 ~6.8mm；
- 下面 §6 的「观测锚定局部针孔」仍然有效（它锚的是剪影，不依赖 f）；
  现在有了真实 `T_base_cam`，可以不再用等效焦距近似，但要改渲染得同步改相机位姿。

**这决定了 up 视图该怎么渲**：球的**法线图只取决于「相机看球心的方向」，不取决于焦距**。
所以 up 视图可以把渲染**锚在观测上**（形心 + 像素半径），而不损失正确性 ——
但**锚这件事必须写在图上**，不能假装 up 相机标定过了。

### 6. up 视图的 L1 换成**球网格**（`up_local_cam`）

原来 up 视图画的是 `BS.draw_ball` 的解析圆。现在按上面 §5 的结论走**观测锚定的局部针孔**：
球心落在光轴上、主点取观测形心 c、焦距由「渲出的剪影半径 = 观测半径 r_up」反解
（`f = r_up·√(d²−R²)/R`，展开回一阶正好是 `spm·H` —— 也就是 `BS.UP_CAM_H_MM`
与 `spm` 早就隐含的那台相机，不是临时凑的）。渲染 `MR.uv_sphere(12mm, 36, 72)`，
着色用同一支实测光 + `ball_material()`。

**自检（41 帧抽样，f246~f406）**：

| 量 | 结果 |
|---|---|
| 网格剪影半径 − 观测半径 | 中位 **−0.01px**，max\|·\| **0.05px** ⇒ 锚定法确实把剪影钉在观测上 |
| 球上被镜面项洗白的像素 | 中位 **0.0%**，max **0.0%** |
| 擦除区残留方块黄（严 S≥150） | min/中位/max **全 0** ⇒ L0 在 up 视图没有漏擦 |
| 球被原帧挡回 px | 157 / **639** / 1267 ⇒ 夹爪确实挡在球前面（见 §7） |
| 红线（掩码外被动过的帧） | **0/41** ✔ |

（旧表里那两行 `L2 手指 px` / `亮白判据` 已随 §7 的改判废除，数值保留在 §7 的对照里。）

⚠️ 图注里写明了「local pinhole anchored to observation; up axis ~20deg off」——
这个相机假定**垂直下视**，真 up 光轴斜 ~20°，所以球的**法线图**会差同量级的一个旋转，
**着色**跟着差一点；**剪影不受影响**（锚死的）。

**2026-10-20 更正（像面 roll，比倾角严重得多）**：上面的合成相机还隐含了
**像面 x 轴对齐 base x**。真实 up 相机（2026-10-19 外参）的像面 x 是
**(0.161, −0.987, 0.017)** ≈ **−base y** —— 和假设差 ~90° 的 roll。
球和立方体看不出来，但**长条物**一旦按真实夹取朝向摆，投影就会转到**相反方向**
（用户实测：「front 往左转、up 往右转」）。修法：`up_cam_from_area(..., R_cam=...)`
/ `fit_up(..., R_cam=...)` 用真安装旋转（位置和 f 仍锚在观测形心），
`pose6d_up_fit.py --up-rot real`（默认）自动传入；同时 up 也用和腕视图**同一个**
`R_fixed = R_gripper @ GRASP_R_OFFSET`。修后 f246 长轴的像面倾角：
up **−67.7°** / front **−19.2°**（同向；数值差是视角差，不是姿态不一致）。
代价：橡皮 f246 的剪影 IoU 0.728 → 0.583 —— 旧高分是用错误 roll 凑出来的。

### 7. up 视图的 L2 定稿：**球只画在「旧物体露出来的地方」**（2026-10-15）

用户原话：_「在 up 摄像头里夹取的物体也就是小球有一部分怎么在夹爪上了……上边一定是夹爪在
挡住小球，而不是小球挡住夹爪」_。旧实现按**颜色**判哪些像素要贴回（先 `V≥218 & S≤40` 亮白、
后改 `S<60` 低饱和），两条都错，而且是**结构性**的错：

| 判据 | 每帧漏/错多少（球盘内） |
|---|---|
| 亮白 `V≥218 & S≤40` | 只认手指**受光的那条芯**，漏 **700~1450px** ⇒ 球盖在夹爪上 |
| 低饱和 `S<60` | 把手指抓全了，但**桌面阴影也是低饱和** ⇒ 球被啃掉一块灰（f246 盘 1298px 里贴回 723px，其中只有 ~222px 是手指） |

**物理上的正解**：方块被夹爪挡住的那一大块，球**同样**该被挡住 ⇒「球能画在哪」由
「旧物体在哪儿露出来」定，而这件事就是 `cm`（擦除掩码）。所以合成收敛成一句可检验的话：

> **改动只发生在 `cm` 里。** `bm ∩ cm` → 球；`cm − bm` → 补好的背景；`~cm` → **原帧逐位**。

`cm` 的现成性质正好对上三件事：它已剔掉受光的手指（`up_erase_mask` 内部 `& ~dilate(亮白,3)`）
⇒ 手指那侧球自动停手；手指的**暗面**本来也进不了 `cm`（S≈25 < 松门限 45）；它自带的 5×5
椭圆外扩（±2px）正好当「球 r=12mm 比方块半宽 10.75mm 宽出来的 1.25mm ≈ 2.4px」。
⇒ **与光照无关、与颜色阈值无关**，换工作台/换光都不用重标。

代码上 L0 也跟着改了：**只擦物体、不再把整个球盘并进擦除掩码**（以前并球盘是因为球要铺满
整盘；现在盘内要逐位回原帧，擦了再贴回来等于白擦，还会把盘内真桌面换成环上中位色）。

**段级数字（`--sweep-up --stride 4`，41 帧 f246~f406）**：

| 量 | min | 中位 | max |
|---|---|---|---|
| 球剪影 px | 1251 | 1634 | 1903 |
| **球露出 px** | 410 | **711** | 1709 |
| **被原帧挡回 px**（夹爪在前） | 157 | **639** | 1267 |
| 越出旧物体轮廓 px（= 球宽出来的 ±2px 环） | 118 | **165** | 232 |
| 补背景露出 px（方块伸在球剪影外那部分） | 0 | **0** | 2943 |
| 红线：掩码外被动过的帧 | — | **0/41** | ✔ |

- 方块被切成 ≥2 块（手指横跨）的 6 帧里，球被挡回 **67%**（中位）—— 这就是「遮挡发生在
  up 视图」的正面证据，改之前这 6 帧是**球盖在夹爪上**。
- `outside_px` 现在是**构造性 0**（不是调出来的）：`out[cm==0] = up[cm==0]` 逐位贴回。
- **唯一一处「编内容」**：方块（对角 30.4mm）比球（直径 24mm）大，它伸在球剪影外的部分
  （角、被手指隔开的另一条带）只能靠 L0 补背景顶上 —— 那一片是**补的，不是拍的**。
  41 帧抽样里 **9 帧非零**，最坏 f334 = 2943px（高举起、方块整个可见的那些帧）。
  补出来的内容与真实背景同色系（暖桌面/指边中间调），肉眼看是「糊了一小块」，不是黄块。

**作废的判据**：本条起，「宁可漏增强不要错增强」**不再作为判据使用** —— 它是当初给
「亮白判据抓不到」找的台阶，实际把用户的抱怨一直留在了合成图里。判断标准回到
**物理对不对**（夹爪在球前面？改动是否只落在该落的地方？），而不是「宁可少做」。

### 8. 注入物从「解析球」换成「**重建的**舵机网格」（新 `mesh_from_views.py`，2026-10-15）

**为什么换**：用户指出 Pose6DAug **不是**把物体的一张照片贴到原位，而是先用图像→三维模型
的办法**重建出物体的网格**。查下来这句批评是对的：原来的 `place_ball` 里，图像只参与了
**位姿**（剪影拟合、`up_local_cam` 反解焦距），**形状**是 `MR.uv_sphere(12mm)` 一个解析球，
一个像素都没参与。对球这一步本来就退化（球只有 4 个自由度，网格没有自由参数），所以换成
**形状不可解析、又自带 CAD 真值**的 SO101 舵机 `sts3215_03a_v1.stl`（45.4 × 24.8 × 39.6mm，
19080 面）。**球的解析路（`--radius-mm`）原样保留作对照臂。** 真照片采集本轮不做（只写协议）。

`mesh_from_views.py` 就是这一步：剪影雕刻（visual hull）→ marching tets → 三角汤网格。
自检 **两条都过**（`--selftest`，解析球 + 舵机）。产物 `calib/recon/<part>_v*_h*_m*.stl/.json`。

#### 8.1 三个踩过的坑（都有实测数字，别再踩）

**① 顶点焊接必须规范化，否则全是假裂缝。** 同一条格棱在两个相邻四面体里可能以 (a,b) 或
(b,a) 出现，两种写法算出的交点差几个 ulp，而 `np.unique` 是按位比较的 ⇒ 同一个几何顶点被
当成两个。解析球上量出 **有向边违规 27、边界边 86**。改成「统一从**扁平化索引小**的格点出发
插值」后 **两项都归 0**。

**② 小面积 ≠ 可丢。** 我曾把退化面判据设成 `area2 <= 1e-12`（想顺手清掉纳米级碎片），
结果**真的在网格上开洞**：解析球多出 **328 条边界边、聚成 67 个 5~7 顶点的小环**。
原因：格点场值 |f| 微小但**非零**时，同一顶点引出的两条棱交点相距约 1e-9m，面积确实是 1e-12
量级，但它们在拓扑上是**必需**的（相邻三角形指望它们配对）。判据必须是 **`0.0`**（只丢逐位
重合的面）—— 而且丢零面积面反而更干净，否则留下自环 (a,a) 破坏「每条有向边恰好一次」。

**③ 场定向在 VH 的尖脊上会退化成抛硬币。** 舵机修好 ② 之后仍剩 **有向边违规 17**（边界边 = 0）
—— 是**朝向不一致**，不是开裂。溯源：涉事 27 个面的 `|fp−fm|` **全部低于全场 p1 = 0.435**
（最小 0.0019，全场中位 0.73），且全部落在 **x≈13.6mm 一条 2.3mm 厚的脊线**上。
机制：`f = min_i Φ_i` 在尖脊处有折点，跨脊面质心 ± εn 落在折点两侧 ⇒ `fp ≈ fm`。
解法是**两段式定向**（`_orient`）：按 `|fp−fm|` 从高到低播种，再沿「共享棱」把朝向**传播**
出去（共享棱要求两面反向使用它，所以邻居由拓扑唯一确定，不再问场）。改完有向边违规 = 0。
**顺带把一个自欺的指标变成真指标**：`winding_ok` 以前恒等于 1.0（自己验自己），
现在是「拓扑推翻场的比例」—— 舵机 4/240588 = **0.999983**（margin 0）/ 20/232428（margin 1px）。

#### 8.2 结论：**VH 在像素化剪影下是单边「内缩」的**（与教科书相反，必须报出来）

教科书说 `VH ⊇ 物体`（每个锥都含物体 ⇒ 交也含）。**这条只在剪影精确时成立。** 实测：

| 条件 | 体积半径（真值 20.000mm） | 折算成剪影半径 |
|---|---|---|
| 完美**解析圆盘**掩码（不经光栅器） | 19.893mm（−0.107mm） | −0.53px |
| **光栅化**掩码 | 19.741mm（−0.259mm） | −0.42px |

机制（三条都验过）：① 像素化剪影边界的**最小**径向半径 ≈ r_true − 1px（是最小不是平均）；
② `sdf_view` 的零集比「最外圈内像素心」再外扩 0.5px；③ **VH 是取交 ⇒ 取了那个最小值**。
⇒ 有效剪影半径 ≈ r_true − 0.5px，投影回物空间 `0.5px·z/f = 0.31mm`，与实测吻合。
**图的独立佐证**（见下）：从任意方向看，`recon-only = 0~31px`、`GT-only = 1099~1346px`
—— 重建**从来不越出**真剪影，只会漏。这是**分辨率**效应（像素更细/相机更近就变小），
不是代码错，也不是可以用常数内外扩糊过去的偏差（它随 θ_c、随掩码形状变）。

#### 8.3 `carve_auto`：外扩 20mm 是**多算的**，粗到细快 3.3×

计划里沿用的「包围盒外扩 20mm（因为 VH 可能长到凸包）」依据错了：`VH ⊆ conv(S) ⊆ bbox(S)`，
后一项是包围盒定义 ⇒ 细格只要 `bbox(S)` 加几格余量。做法是**粗到细**（粗格找占据体 → 只雕它的
包围盒），粗格先做 3³ 膨胀再取包围盒，且**粗/细格贴边都会放大重来**（宁可多给不可少给）。
实测舵机 177³ = 5.5M 格 → 粗 39³(2mm) + 细 111×71×95(0.5mm) = 0.75M 格；
`--selftest`（球 + 舵机两例）总耗时 **>240s → 72.6s**。
⚠️ 粗格体素边长是 `coarse·h`（默认 4×h = 2mm）：**薄片状物体要自己把 `coarse` 调小**，
漏掉的薄片**不会**让细格贴边，因而逃过检查。

#### 8.4 两个「静默失败」陷阱

- **`cv2.imwrite` 目录不存在时不抛异常、只返回 False。** 脚本照样打印「→ 图」，其实一个字节
  都没写 —— 我差点据此报告一张不存在的图。现在 `_figure` 显式建目录 + **检查返回值**。
- **`cv2.putText` 不认 `\n`**（会渲成乱码方块），且单行过长会**被画幅裁掉**。`_lab` 现在支持
  多行，并在超宽时**抛异常**而不是默默截断。

舵机、50 视角、体素 0.5mm、margin 1px：**232428 面，有向边违规 0，边界边 0，自洽率 0.999914**。
